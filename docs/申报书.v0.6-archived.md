# mcpconftest — MoonBit 生态共建大赛 10 月参赛申报书

## 项目概述

**mcpconftest** 是一个纯 MoonBit 编写的 **MCP 协议一致性测试套件 + CLI 工具**。它能启动任意 stdio MCP 子进程，通过 JSON-RPC 标准输入输出与之通信，并自动验证目标服务器是否符合 `2026-07-28` 协议规范。

## 项目背景与痛点

| 现状 | 缺口 |
|------|------|
| MoonBit 生态已有 `colmugx/mcp@0.17.4` SDK | **没有任何协议一致性测试工具** |
| 社区 MCP 服务器实现质量参差不齐 | 开发者只能靠手工抓包或肉眼比对验证合规性 |
| 现有 MCP conformance 工具链（Python/JS）与 MoonBit 生态割裂 | MoonBit 项目无法方便地自检，也无法在 CI 中集成 |

## 已有基础

本项目并非从零开始。已完成的先行调研：

1. **8 月 rx-mbt**（响应式运算符库）与 **9 月 FIST-Mbt**（129 工具 MCP 服务器框架）——熟悉 MoonBit 生态与 MCP 协议栈。
2. 完成《2026-10 MoonBit 参赛方向推荐》调研文档，确认 mcpconftest 为**生态最稀缺方向**。
3. 完成项目骨架搭建，`moon check` 已通过（0 错误）。

## 核心功能（当前实现）

1. **Initialize 握手检查**：验证 `jsonrpc: 2.0`、`serverInfo`、`protocolVersion` 字段。
2. **Capabilities 检查**：当服务器声明 tools 能力时，检查其是否真实暴露 tools 接口。
3. **tools/list Schema 检查**：每个 tool 必须包含 `name` + `description`。
4. **tools/call 错误路径检查**：调用不存在的 tool 时，服务器应返回正确的 JSON-RPC 错误码（`-32601`）。
5. **Notification 健壮性检查**：发送未知 notification 后，服务器不应崩溃。
6. **幂等性检查**：重复调用 `tools/list` 应返回一致结果。

## 技术选型

- **语言**：MoonBit（`js+native` 双目标）
- **协议**：stdio JSON-RPC 2.0，与 MCP SDK 对齐
- **依赖**：零外部依赖（仅 `moonbitlang/core`）
- **测试**：内嵌 `types_test.mbt` + 独立的 fixture server 套件

## 项目价值

1. **填补生态空白**：MoonBit 第一个 MCP conformance 工具。
2. **可复利**：FIST-Mbt 的 129 工具可直接作为被测对象；其他 MoonBit MCP 项目可集成自检。
3. **小而美**：核心逻辑几百行，MVP 可在 3 周内交付。
4. **差异化**：8 月做库（rx-mbt），9 月做框架（FIST-Mbt），10 月做**测试工具链**——覆盖生态不同层。
